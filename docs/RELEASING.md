# PatentPulse release checklist

This process creates a stable public snapshot without publishing local working
data, credentials, or ingest state. The scheduled ingestion automation is
paused during release preparation.

## 1. Confirm the snapshot is releasable

```powershell
python -m patentpulse.ingest status
python -m pytest tests -q
```

The status output must show no pending, running, or failed source files. The
exporter independently enforces this invariant. Do not edit `manifest.json` to
bypass it; either ingest the missing source successfully or explicitly ship a
new, clearly documented partial-snapshot workflow in a future release.

Review [DATA_LICENSE.md](../DATA_LICENSE.md) and the [USPTO Terms of
Use](https://www.uspto.gov/terms-use-uspto-websites). The software is MIT;
dataset snapshots use Hugging Face's `other` label and the data-rights notice.

## 2. Build and validate an immutable snapshot

Use an empty directory on a volume with enough free space:

```powershell
python -m patentpulse.hf_release export `
  --input data/processed/patents.jsonl `
  --output E:\releases\patentpulse-v1

python -m patentpulse.hf_release validate `
  --release E:\releases\patentpulse-v1
```

The output contains `README.md`, `DATA_LICENSE.md`, `release_manifest.json`,
and Parquet shards. Keep the manifest and data-rights notice with the release:
they record reuse conditions, counts, temporal split totals, and the canonical
digest.

## 3. Publish to Hugging Face

Authenticate interactively if needed, then inspect the account without printing
any token:

```powershell
hf auth whoami
hf repos create <namespace>/patentpulse --type dataset --public
hf upload <namespace>/patentpulse E:\releases\patentpulse-v1 `
  --type dataset `
  --commit-message "Release PatentPulse v1"
```

Use the dataset repository's default README generated by the exporter. Verify
the Hub viewer exposes the Parquet config and that the card retains its `other`
license metadata and provenance notice.

## 4. Publish the GitHub source release

Review the working tree so that it contains source, tests, and documentation,
but not generated corpus data, local manifests, raw archives, credentials, or
Hugging Face tokens. Commit and push only after that review. Create an annotated
source tag such as `v1.0.0` and draft a GitHub release that links to the exact
Hugging Face dataset revision and repeats the data-rights notice.

Do not attach the local SQLite database, JSONL ingestion artifact, raw USPTO
archives, or `data/manifest.json` to the GitHub release.
